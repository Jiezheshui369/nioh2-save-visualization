# 配装册持久化与同步恢复 · 0.7.8

## 修复的问题

此前写入 IndexedDB 失败会退回 localStorage，但下次读取可能优先取到旧数据库并清除新的回退记录；多次并发收藏还可能读取相同旧列表并互相覆盖。`slice(0, 50)` 会静默丢弃超限记录，空数据库可能重新迁入用户已经删除的旧记录。

本轮规则：

- 同一 IndexedDB readwrite 事务内读取、修改和写入；只有事务 complete 才算成功，abort 保留旧状态。每次关闭连接。
- 只有环境没有 IndexedDB 才使用 localStorage；数据库打开或写入失败不偷偷切换后端。
- 只在数据库尚无 `all` 键时迁移旧数据；空数组是明确状态。提交后且原始文本未变化才删除已迁移副本。
- 数据库已有内容时，不删除另存的旧恢复副本，也不盲目合并（避免复活已删除配装）。历史失败留下的歧义副本仍保留；暂无专门的恢复选择界面，后续恢复前须先备份两处。
- 最多 50 套；新增／合并超限整体拒绝，不淘汰旧配装。若历史库已经超过 50 套，仍完整读取，可逐套移除；未处理前拒绝生成不完整档案包。
- 结构损坏或存储访问失败不冒充空配装册；界面提供重试，禁止未完成初始读取时收藏，保存中防止重复点击。

## 部分接收

角色与配装册是不同数据库，不能假装跨数据库原子提交。角色保存成功但配装册失败时：

1. 保留并显示已提交的角色，同时展开“接收尚未全部完成”说明。
2. 不记录为完整保存的 revision，也不显示全部同步成功。
3. 处理容量／存储问题后回到同步页，点击“接收最新角色”；同一 revision 也重新合并，不要求转存 JSON。
4. 自动轮询只在同步页和应用前台运行，完整成功的相同 revision 自动跳过重复写入。显式手动接收不跳过。

迁移不改变存档解析，不写回游戏文件，不改变已经确认的四页格局；React／前端技能用于保存锁、状态与异常提示，没有新增 Figma 设计。

## 回归范围

fake-indexeddb 覆盖多连接并发、提交前 abort、容量满、迁移失败保留源、空库不复活、迁移中源被修改、超限旧库恢复和并发合并。React 覆盖读取失败重试、连点保存、删除失败保留、同版本同步重试、部分保存以及关闭页面暂停轮询。集成测试由模拟原生插件返回合成角色，实际使用测试 IndexedDB 保存，重新挂载验证恢复。

这些不是 Android／iPhone 真机存储耗尽实验；不要为了测试填满个人手机、卸载旧版或清除应用数据。
