# 词条值与证据契约

解析器源码 0.9.9 / 应用源码 0.7.16-dev，2026-09-25。本轮源码交接包含这些变更；已冻结 0.7.15 安装包仍含 0.9.7。此变更不是最终人物属性计算器，也不是全部字段已解析。

## 可选扩展

装备、已装备记录与绘卷的 `effectValueDetails` 数组和 `effects`、`effectIds`、`effectMagnitudes` 一一对应；空槽沿用原解析器跳过规则。旧档案可没有本字段；新元数据必须完整对齐，格式错误时不覆盖旧离线档案。

每条保留原始小端 uint32 `rawValue`，范围 0 至 4294967295 是存储类型边界而非游戏属性限制。`kind` 与 `encoding` 组合如下：

| kind | encoding | 显示含义 |
| --- | --- | --- |
| numeric | verified-id | 该 ID 已核对编码，显示数值；不等于人物最终总值 |
| numeric | legacy-cap | 沿用旧社区 CAP 启发式，显示数值并标注单位待复核 |
| grade | verified-id | 仅显示已核对的 ID/原值/标签组合，不是可相加的数值 |
| condition | not-decoded | 条件词条，不当成数值加成；不推断是否生效 |
| non-numeric | not-decoded | 目录标记非数值词条，不把原值 0 当成效果强度 |
| unresolved-grade | not-decoded | 档位未解析，不拿目录参考最高档位代替实际档位 |
| unverified-unit | not-decoded | 已知旧单位推测不可靠，暂不显示猜测数值 |
| unknown | not-decoded | 数值未解析 |

`effectMagnitudes` 仍为 string/null；非数值和未确认单位输出 null。真实原值单独保存，不添加到人物属性。前端和 Python 共用 `agent/data/effect_value_rules.json`，防止旧档案与新解析的特殊 ID 规则分叉。

## 当前规则的边界

- 深奥八个 ID：DAC2、B613、2BC3、23E8、DFF0、AE5A、6B7D、2B06。只分类为条件；不把 raw=150 渲染成加成，也不根据目录 CAP 确认修改存档的实际生效阈值。
- 0.9.8 新核对三项魂核妖力 ID：B4D8 原值21对应截图2.1，5B76 原值16对应1.6，5CFF 原值15对应1.5。两份已有副本中对应魂核名称、等级、原值一致，截图明确凭附中。按十分之一固定值解码，不是百分比，不等于人物最终妖力。
- 妖力其余三个 ID：523B、D83E、2317 仍未验证，不推广以上规则。目录 CAP 含整数和小数，不是编码规范。
- 旧档案的这三个新核对 ID 若缺少明确 numeric/verified-id 元数据，继续显示单位未解析，不能让旧错误百分比因规则升级而重新出现；用户需电脑重新解析并主动发布。
- 已核对的三项编码仍保留：91A6 重量小数；164A、9158 百分比小数。此前截图核对证据见 STATUS_PARSER_RESEARCH_20260923.md。
- 0.9.9 新核对六项魂核百分比 ID：E5E7、823B、9D39、9BF2、8D1A、AD6B，按十分之一百分比解码。ID 明确规则优先于目录 CAP；不由这些记录计算角色最终总效果。
- 0.9.9 档位是稀疏映射：3961/raw13→AA、9AD2/raw13→AA、24E8/raw8→B+。未知相邻原值仍输出 null / unresolved-grade，不推广到其他 ID 或建立全局档位阶梯。前端要求 grade/verified-id 元数据与同一 ID、rawValue、显示标签一致，旧档案不自动追认。
- 已确认的十分之一单位使用整数拆分格式化，保留 uint32 大值精度，不应用游戏正常数值上限。
- 前端在计算已验证覆盖率及显示新数值时，对这些ID的单位/原值/显示字符串做一致性检查；元数据自称verified-id但显示值不符时保留未解析，不修改导入档案。
- 其余 CAP 启发式暂保留兼容性，但必须标注未复核；覆盖率不再把它算作已验证数值。旧档案缺少证据元数据时不追认已验证。
- 非数值／档位分类来自已有目录，不代表完整解码，更不代表当前守护灵、武器、魂核或绘卷已激活。

## 0.9.9 补充证据与升级兼容

同一批截图与两种已有副本重读核对：三枚魂核共13条词条、12个不同ID的原值和显示值一致，输入读取前后不变。私人核对脚本及结果在 Windows 本地，不进入迁移源码。两个副本的相同配装不是两个独立变化样本，不能用于证明未知选择关系。

单份副本的308条装备/绘卷记录共1620条词条：numeric1089、grade4、unresolved-grade120、condition24、non-numeric174、unverified-unit10、unknown199；编码verified-id53、legacy-cap1040、not-decoded527。这是库存词条覆盖，不是最终属性覆盖。164行角色核对仍是11直接匹配、37待验证面板、58仅来源候选、58未找到同名来源。

`grade` 是新元数据类型。旧0.7.15及更早客户端可能拒绝带此字段的新档案，而不是自动显示新档位；应先把电脑和手机都升级到包含本契约的构建，再由电脑重新解析并主动发布。不要删除原始证据、把档位冒充numeric或降级类型来绕过旧客户端验证。旧档案仍可由新版读取，原有离线数据不会仅因本次源码变更自动被替换。

源码交接不等于新安装包已发布。Mac/手机端的设备验收独立进行，当前验证见 RELEASE_0716.md 与源码包旁 VERIFIED.md。

`node scripts/check-effect-contract.mjs --python python` 在内存生成合成记录，实际执行Python解析器及TypeScript的结构校验、词条展示、覆盖率和档案导出/再校验，覆盖19个跨语言用例。没有读玩家文件，也不是原生设备测试；CI中同样执行。
