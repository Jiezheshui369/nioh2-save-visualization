更新于 2026-10-03。状态：需求确认记录，不是实现或部署完成报告。用户现已授权上传筛选源码与文档到现有私有 GitHub 仓库，并在 Mac 优先开发 iPhone，暂用自己的 Windows 电脑作为服务器。没有授权上传玩家存档、购买服务或开放公网。

历史实施计划：[第一版改造与排期审核稿及确认记录](V1_REBUILD_REVIEW_20260929.md)。其中 Windows＋Android 优先与 10 月 2 日周五晚验收是旧安排，现以 iPhone 接手优先；未商定新截止日期。范围确认不是功能已实现，也不等于授权购买服务器或修改域名配置。

## 已确认的产品方向

- 产品是可扩展的多游戏存档资产库；仁王2是目前唯一已有解析器的游戏，不是整个应用的数据模型。
- 电脑掌握存档并进行只读处理，服务器保存账号下的已上传数据，手机登录同一账号取得数据。新主流程不以同一Wi-Fi或扫码为前提，不要求用户手动传JSON。
- 用户可以明确点击同步某个游戏，或同步全部已管理游戏。“全部”不是扫描/上传整台电脑的所有文件。
- 未点击同步，手机保持上次成功保存的本地版本，可离线查看；应用打开、恢复网络或服务器出现新版本不能悄悄替换展示数据。
- 服务器上的最新版本与手机缓存版本是两份独立状态。“电脑已上传”不等于“手机已接收并保存”。首次无缓存时显示尚未同步。
- 仅向用户指定的私有 GitHub 仓库上传经过筛选的开发源码和文档，保留远端历史；不上传私人存档与研究证据，不改成公共仓库。

## 实施边界与拟定验收

- 通用层负责账号、游戏标识、存档/角色身份、版本、同步状态和离线存储；游戏适配器分别负责文件识别、解析、校验和专属展示。不能假设每个游戏都有装备、魂核或绘卷。
- 同步、缓存与任务至少按账号和游戏隔离，同一游戏多个存档/角色不能无意合并；具体多槽位选择交互再确认。更换账号不能看到另一个账号的缓存。
- 单游戏同步只更新所选游戏，其他游戏缓存不变；一次“全部同步”分别列出每个游戏的结果，允许部分成功，但不能提示全部成功。
- 校验及本地保存成功后，才切换该游戏的离线版本。网络中断、解析失败、未知数据版本或磁盘失败均保留旧数据，不能清空或用零值替代。
- 每个游戏显示本地最后成功同步时间，云端版本信息只能在实际获知时展示。过期状态须明确，不能用打开页面的时间冒充同步时间。
- 不把较晚收到的旧响应覆盖成新版本；多电脑/多存档版本冲突需要明确规则，不自动以客户端时间戳断言哪个存档更正确。
- 云同步只更新应用的资产快照，不表示允许把服务器文件写回或覆盖游戏存档。原始存档继续只读。
- 后端需要独立账号鉴权、玩家数据隔离、受保护的传输与上传限制；不得把当前仅限局域网的配对监听器直接开放到公网。
- 不新增没有证据的解析结果。仁王2未完成的37项最终属性及116条总效果仍待解决，支持多游戏扩展不等于已经解析其他游戏。

## 已确认的实施范围（2026-09-29 后续回复）

1. 电脑自动上传按游戏授权开启，默认关闭，并保留手动上传；必须校验副本稳定性，不把退出游戏直接当成安全上传信号。
2. 手机只主动下载服务器已上传的版本，不远程要求电脑重新采集。没点同步不替换离线快照。
3. 第一版只上传解析结果，不上传原始存档，不提供游戏存档回写恢复。
4. 暂不开发第二款游戏解析。游戏库可使用“仁王3”占位，明确标注“暂未支持”；不展示虚构角色、不调用仁王2解析器、不加入“同步全部”的执行清单。第二合成适配器仅用于开发测试，与用户占位卡分开。
5. 用户已确认域名为 `jiezheshuizz.com`，在阿里云购买；10 月 3 日确认暂用自己的 Windows 电脑作为服务器，不购买云主机。跨网络访问方案、DNS 及具体对外部署另行确认；不索取聊天中的密码或密钥。服务器休眠或断网时无法获取新版本，手机已保存数据仍应可离线看。
6. 历史周五验收已过，新截止日期待定，使用 Australia/Sydney。保留仁王2内部格局，平台名称不擅自更换。
