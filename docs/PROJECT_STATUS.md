## 已完成的可用闭环

1. 本地 Agent 等待源存档稳定后，以只读模式读取已识别的主存档、游戏备份档与 Steam 自动云存档标记。
2. Agent 将文件复制到项目的独立快照目录，并逐个校验源文件与副本的 SHA-256。
3. 固定使用 Katana 的 Nioh 2 解密模式处理副本；应用没有加密、重签名或写回命令。
4. 解析器从解密副本提取结构化 JSON，网页端通过本机 API 展示。
5. 用户可在网页中刷新当前存档、导入 JSON、浏览历史快照，并自动比较当前记录与上一份记录。
6. 用户可显式开启带临时口令的局域网模式，在同一家庭 Wi-Fi 上进行手机真机测试；默认仍只允许本机访问。
7. Agent 可发现多个 Steam 账户与 `SAVEDATAxx` 角色槽位；网页只接收匿名来源编号、账户尾号、槽位名和写入时间。
8. Windows x64 目录版包含网页、Agent 与固定哈希解密器，并在发布前自动拒绝任何混入的存档文件。
9. 手机浏览器会保存最近实际浏览过的最多 20 份结构化快照，也可在安全页一次保存最近 20 份；电脑离线时仍可查看这些历史记录，原始存档不会进入浏览器。
10. 安全页以本机 `remotecache.vdf` 只读诊断“游戏存档 → Steam 云端 → 手机快照”三层状态。
11. 主体验已转向角色资产化：用户可将当前装备命名、备注并保存为最多 50 套独立本机配装，之后复制纯中文分享摘要。
12. 时间快照、哈希与同步诊断继续保留，但不再作为首页的主要叙事。
13. 角色档案与设备配装册可合并导出为版本化档案包，并在 iPhone 端导入 IndexedDB；导入完成后数据查看不依赖电脑在线。
14. 生产 Service Worker 会在安装阶段预缓存构建生成的 JS/CSS，满足 HTTPS 部署后的离线启动基础。

项目已提供只读差分工具，可对两个**解密副本**生成紧凑的偏移报告：

```powershell
python -m agent.binary_diff .local/copies/before.bin .local/copies/after.bin --copy-root .local/copies --output .local/diffs/mission-change.json
```

不要把原始存档传给这个命令；研究流程应先通过安全快照管线生成副本。0.7.7 起必须指定副本根目录，输出必须在该目录之外且不能已存在。差分报告有数量及十六进制预览上限，依然属于私有数据，不能上传 GitHub。
