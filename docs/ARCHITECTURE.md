# 架构与数据流

## 最新方向（2026-09-29）

用户确认改为多游戏存档资产化平台：电脑采集/解析、自有服务器按账号保存、手机同账号按游戏或全部已管理游戏手动同步，并离线保留上次成功数据。《仁王2》只是首个解析适配器。上传触发与原始存档备份范围尚未定案，完整边界见 MULTI_GAME_SYNC_V1.md。

这是目标架构，尚未实现账号云同步；现有实现为 LOCAL_SYNC_PROTOCOL.md 中的局域网直传。不得把现有局域网服务直接暴露公网代替后端，不擅自自动上传。GitHub上传已暂停。

## 历史架构草案（2026-09-21，不作为当前同步需求）

以下保留早期文件导入及可选中继的设计背景。其中“V1手动文件”、环境安装缺口、端到端密文中继及发行安排并非当前完成状态或新的已确认决策；最新方向以上文及 CURRENT_GOAL.md 为准，JSON仅作高级备份恢复。

### 本地优先的“电脑采集 + 手机随身查看”

```text
GitHub Releases
   ├─ Windows 桌面应用（安装包/便携版）
   └─ Android 应用（APK）

玩家把 SAVEDATA.BIN 拖入桌面应用
                 │
                 ▼
      只读打开 + 稳定性检查 + SHA-256
                 │
                 ▼
        创建独立、不可写的工作副本
                 │
                 ▼
       仅对副本解密 → 解析 → 校验
                 │
          ┌──────┴────────┐
          ▼               ▼
   电脑端本地可视化    导出角色档案包
                          │
              分享到手机 / 文件中打开
                          │
                          ▼
                   Android 本地导入
                          │
                          ▼
              设备数据库 + 离线查看/分享
```

桌面应用的“拖入”只代表选择输入文件。它不会在原位置解析、解密或改写存档；真正的工作从经过哈希校验的独立副本开始。项目不提供写回、重签名或覆盖原存档的入口。

这个架构把两件事分开：

- **电脑端**掌握游戏存档文件，负责只读采集、解密、解析、版本兼容和完整可视化。
- **手机端**只接收版本化的结构化角色档案，不接触 Steam 密码、Steam Cookie 或原始存档；导入后可离线浏览和社交分享。

## 第一版传输方式

2026-09-21 实现进展：已建立 Capacitor Android 壳，共用 React 展示和档案格式；手机模式只读 IndexedDB，不调用电脑 API。导入入口为应用内系统文件选择器，原生系统分享适配已接入；从其他应用直接“用此应用打开”的接收入口尚未实现。当前缺少 JDK/SDK，尚未编译 APK 或完成原生验收，详见 `ANDROID_DEVELOPMENT.md`。

第一版采用显式档案包：电脑端点击“发送到手机/导出档案包”，生成一个不含原始存档、密钥、Windows 路径和哈希指纹的版本化文件；用户可通过聊天软件、数据线、网盘或二维码附近传输，把文件交给 Android 应用打开。

这不是最终最省事的体验，但它不需要服务器、不依赖同一 Wi-Fi，且电脑关机后手机仍可查看。它也让 GitHub 发布的早期版本可以在很少用户的情况下运行。

## 后续可选同步层

当手动档案包闭环稳定后，可加入账号无关的端到端加密同步：

```text
桌面应用 ──本机加密──► 只保存密文的中继服务 ──► Android / iOS 本机解密
```

配对密钥只存在用户设备。服务端不能读取角色、装备或进度。局域网二维码直传可作为快捷方式保留，但不能成为跨网络查看的唯一方式。

## 备用架构：Steam OAuth + Steam Cloud

Steam OAuth/受限云存档读取保留为备用路线，不作为当前产品成立的前提。只有在 Valve 明确向本项目提供可用客户端身份、`read_cloud` 类授权范围，并允许读取 AppID 1325200 的用户云文件后才评估接入。

即使未来获批，这条路线也只替代“取得加密存档”一步；《仁王2》的解密、版本化解析、隐私裁剪与移动展示仍需要本项目自己的管线。项目永远不通过抓取 Cookie、模拟 Steam 客户端或收集 Steam Guard 凭据来绕过授权。

## 跨平台模块边界

- `SaveSource`：桌面拖放、文件选择以及以后可能存在的 Steam Cloud 来源；输出只读输入流。
- `SnapshotGuard`：等待稳定、计算哈希、复制到独立工作区、再次校验并把副本设为只读。
- `Nioh2Decoder`：只接受工作区副本，输出独立的解密副本。
- `Nioh2Parser`：把解密副本转换成带模式版本和置信度的结构化档案。
- `ProfileContract`：电脑、Android、未来 iOS 共同消费的版本化数据契约。
- `DesktopShell`：拖放、解析状态、电脑端可视化、档案包导出和诊断。
- `MobileShell`：档案包导入、设备数据库、离线浏览和分享卡。
- `SyncProvider`：可插拔；V1 是手动文件，后续可增加局域网直传和端到端加密中继。

当前代码中的对应模块：

- `agent/nioh2_agent.py`：快照、哈希链、本地 HTTP API 与刷新编排。
- `agent/parser.py`：解密副本到版本化 JSON 的纯解析逻辑。
- `agent/data/`：物品、装备、恩宠和词条映射。
- `src/assetPackage.ts`：角色档案包、隐私裁剪与导入校验。
- `src/snapshotCache.ts`、`src/buildLibrary.ts`：设备离线历史和配装资产。
- `src/App.tsx`：现有 Web/PWA 展示层；将作为桌面壳与移动壳的交互原型。

## 发行边界

- Windows：GitHub Releases 提供签名后的安装包和可选便携版。
- Android：早期由 GitHub Releases 提供 APK；正式扩大用户群前再评估应用商店。
- iOS：复用数据契约和 UI 系统，但需要在 MacBook 上使用 Xcode 完成签名、TestFlight 和 App Store 流程。
- GitHub 仓库和发布产物不得包含任何真实存档、解密副本、用户档案包或可识别用户的路径/哈希。
