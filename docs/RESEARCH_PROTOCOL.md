# 只读存档研究流程

更新：2026-09-25。先研究已有独立副本；不要求用户重收已经收齐的木灵，不强迫更换装备、洗点或修改存档来配合开发。

## 当前工作方式

1. 只使用项目已生成、校验过的解密副本，记录读取前后的哈希；不得直接运行编辑器操作游戏目录。
2. 按内容哈希去重。十几份相同存档不是十几份独立证据；SYSTEMSAVEDATA 不当作角色 SAVEDATA。
3. 截图仅用作带来源的核对记录；不把截图常量、同值搜索结果或研究偏移写入生产人物字段。
4. 候选关系需核对记录大小、边界、空槽、索引与完整记录体，而不是只比较名称或词条。
5. 报告保存在 `.local/`，新建目录或文件，不覆盖旧报告；报告中的哈希、二进制预览和玩家资料均不得迁移到 GitHub。

```powershell
python -m agent.binary_diff .local/copies/before.bin .local/copies/after.bin `
  --copy-root .local/copies --output .local/diffs/new-comparison.json
```

此示例路径必须替换为真实的**已有副本**。工具不会帮你复制原始存档，也不能证明随意命名为 copies 的目录就真是副本。输入各限 8 MiB，默认保留最多 4096 个变化区段、每段前 64 字节预览；完整变化字节数和区段数单独统计。截断标记不能忽略。输出必须位于副本根目录之外，不能覆盖任何已有文件。

关联追踪使用 `python -m agent.tools.trace_equipment_links --help`。守护灵候选表必须显式传入研究偏移、行数和选择字段位置；工具不会自动认定当前主副守护灵或佩戴绘卷。

## 什么时候才向用户索取证据

已有资料不足以区分语义时，先说明具体候选及验证目的，优先只要当前游戏界面的截图或名称确认。只有用户愿意时，才请其通过正常游戏操作提供单变量前后状态；不要求不可逆行为或修改原始存档。获取新样本仍通过应用的独立副本管线。

如用户自愿提供前后状态，应记录游戏版本、平台、DLC、角色及任务背景、唯一正常游戏动作、两张状态截图、两个副本编号；避免游戏保存期间采集。截图与副本的时间不一致要明确标记，不能当作反例或命中。

## 发布字段的证据门槛

- 明确偏移、字段宽度、端序、编码和适用游戏版本。
- 排除计时、联网状态、历史配装、库存副本等混淆因素。
- 具有独立证据、尽可能有变化／反向／不同角色交叉检验；相同副本重复运行只算回归检查。
- 区分已确认直接字段、只确认来源词条、活动槽候选、最终值未解析。
- 失败、空槽、未知 ID、越界和截断都有测试；不以公式推算代替直接解析。

研究工具不生成可导入的角色档案；正式解析未知项继续显示“未解析”。
