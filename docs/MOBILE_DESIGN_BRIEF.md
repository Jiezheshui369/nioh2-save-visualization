## 设计目标

手机不是电脑页面的缩小版，而是玩家见面时能在十秒内打开、辨认和分享的“角色资产夹”。首版只显示中文，不先做语言切换。

## 核心页面

1. **导入档案**：解释数据来自哪里、如何从电脑导出，并通过系统文件选择器导入；无演示人物冒充真实存档。
2. **角色总览**：角色等级、八项能力、核心资源与人物详细属性；能力值下方不再显示主力装备。人物属性包括装备负重、敏捷等级、坚韧度、装备/物品掉落率、妖怪化持续时间。
3. **配装详情**：11 个装备槽、绘卷入口、套装组成与分享。装备可展开等级、+值、稀有度、恩宠/套装和完整词条数值；绘卷展示自己的词条。详情使用独立页面或可滚动抽屉。
4. **仓库**：装备/物品两类主标签；装备按刀、双刀、枪、斧、锁镰、大太刀、旋棍、手斧、薙刀镰、机关棍、手甲、弓、火枪、大炮、防具、饰品、绘卷筛选。装备详情与配装共用组件。不显示恩宠件数统计。

## 数据与交互约定（2026-09-21）

- Figma 设计示例必须在画板外注明示例数据，不作为用户真实角色资料。
- `effects`、`effectsZh`、`effectIds`、`effectMagnitudes` 按索引对齐；显示已验证的百分比/平面数值，未解析值显示明确状态，不当作 0。
- 当前 `character` 契约仅有等级、精华、金钱、加点、熟练度与技能点计数；详细人物属性尚未解析。不能仅累加装备词条来冒充游戏内最终面板值。
- 当前 `scrolls` 契约没有佩戴标记；配装必须保留“装备中的绘卷尚未识别 → 查看绘卷库”状态。不得用第一张绘卷或最高等级绘卷替代佩戴关系。
- 仓库列表、配装列表中的装备点击后使用同一详情结构；筛选能清空、展示选中状态，并提供无结果状态。
- 数值与单位清晰分栏；长词条允许换行；完整内容通过滚动访问，底部导航不遮挡内容。
- 现有网页仓库卡片仅使用 `effects.slice(0, 3)`，并以“另有 N 条词条”结束，没有展开入口。这是当前详情缺失的已确认前端原因；设计通过共用完整详情页解决，审查后实现时移除该访问障碍。

## 视觉方向

- 延续现有“墨黑、朱红、旧金、和纸”的编辑式视觉，但减少桌面端的大面积装饰字。
- 品牌统一使用文字 `Nioh`，移除“仁”印章；其余界面暂为简体中文。
- 正文字体优先系统中文宋体/衬线字体，数字使用清晰等宽字体；所有关键操作保证移动端可读和可触达。
- 使用 4/8/12/16/24/32 间距体系，主要触控目标不小于 44 px。

## 游戏视觉素材策略

- 官方网站、官方 Web 手册和 Wiki 的截图用于建立视觉情绪板，研究装备信息层级、状态图标语义、稀有度与恩宠的表现方式。
- 按用户指定，武器类别优先使用 Nioh 2 Wiki 的实际游戏图标；记录原始网址和来源，保留比例。
- 图标建立为本地组件，按 `Game Icons/Nioh 2/Weapons/<Category>` 命名，归入 Figma Assets；页面使用实例。无法加载的图片须记录失败，不用重绘图冒充原图。
- App 内的游戏名称仅用于说明兼容性，并明确项目与 Koei Tecmo、Team Ninja、Valve 无隶属关系。
