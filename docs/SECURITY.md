# 安全与只读边界

## 2026-09-25 原生手机同步边界

当前主路线是独立、用户主动开启的局域网 TLS listener，手机固定证书指纹验证后接收隐私裁剪档案；不是下面历史浏览器 `-Lan` HTTP 入口。完整协议见 LOCAL_SYNC_PROTOCOL.md。iOS 原生证书策略已编写但仍待 Mac 编译及设备负面测试；不宣称已通过完整安全审计。

Android/iOS 不通过 WebView 放宽证书验证；配对只接受规范的 RFC1918 IPv4。两端拒绝重定向、限制响应大小，前端校验嵌套档案结构并在持久化成功后提示完成。未识别字段不填零。原始存档不传给手机。

迁移源码只用 `scripts/prepare_handoff.py` 创建的新 ZIP；签名密钥、缓存、解密样本和角色档案被排除。允许列表和哈希只提供范围/完整性检查，不是所有隐私信息扫描或版权许可证明。首次 GitHub 迁移建议使用私有仓库，用户检查后自行上传。

下方含历史 PWA/LAN 兼容机制说明；不得用它替代原生 TLS 配对通路。浏览器权限策略与原生相机权限是两套独立设置。

## 不变量

- 原始存档目录只作为输入源，所有打开操作均为二进制只读。
- 解密器只接收复制后的快照目录，不接收原始存档目录。
- 解密前后都会重新计算快照文件哈希；源文件和初始副本哈希必须一致。
- 结构化 JSON 发布前再次只读计算原始加密文件哈希；读取期间若游戏写入，放弃本次结果。
- API 默认仅绑定 `127.0.0.1`，不会自动暴露到局域网或公网。
- 只有显式使用 `-Lan` 时才监听局域网；远程 API 请求必须携带每次启动随机生成的临时口令。
- 配对口令放在 URL 片段（`#pair=`）中，不会随 HTTP 请求进入访问日志；前端保存后立即从地址栏移除。
- 页面响应启用严格的内容安全策略，禁止第三方脚本、页面嵌套、MIME 猜测以及相机、麦克风和定位权限。
- 多角色来源 API 仅返回进程内匿名编号、Steam 账户尾号、`SAVEDATAxx` 与写入时间；不返回 Windows 用户名或完整存档路径。
- 应用没有存档写回、加密或重签名入口。

## 数据落点

- 加密快照：`.local/encrypted-snapshots/`
- 结构化快照：`.local/snapshots/`
- 解密器输出：`agent/tools/katana/_OUTPUT/`

这些目录都位于项目内，与原始 Steam/《仁王2》存档目录分离。它们包含玩家隐私数据，不应上传到公开仓库或网盘；项目的 `.gitignore` 已排除 `.local` 与解密输出。

网页的“导出分享副本”会移除原档与解析副本的 SHA-256 指纹，但仍包含角色等级、加点、装备和物品等玩家数据。分享前应确认接收对象；完整研究快照只保留在本机 `.local` 目录。随网页发布的 `demo-snapshot.json` 是人工合成样例，不包含真实玩家数据或存档指纹。

“下载差分报告”只包含两个结构化快照的编号、可选研究标签、解析版本与已支持字段的变化，不包含原始/副本哈希或完整存档内容。它仍可能透露角色等级、物品和装备变化，分享前同样应确认接收对象。

浏览器会把最近实际浏览过的最多 20 份**结构化快照**保存到同源 IndexedDB；用户也可在 Agent 在线时通过“保存最近 20 份”主动准备近期历史。记录按存档时间和快照编号稳定排序，供手机断开电脑后继续查看。原始 `SAVEDATA.BIN`、解密副本和配对口令不会写入该数据库。结构化快照仍包含角色隐私数据；“安全记录”页显示实际数量，并可一次清除全部设备离线副本。

## 已知边界

- 第三方解密器是本地二进制依赖，许可证见工具目录；发布安装包前应固定校验值并进行恶意软件扫描。
- Windows 目录版固定校验 Katana 的 SHA-256（`677F49B8…AFA0E`），再把它复制到应用数据目录运行，避免向只读安装目录写入解密输出。
- 内部测试版尚未进行商业代码签名；受管理的 Windows 设备可能由应用程序控制策略阻止启动，项目不会建议绕过系统安全策略。
- 当前字段映射主要由单一真实样本与公开映射表验证，不能保证所有补丁版本、DLC 状态和极端背包数据都相同。
- “只读”防止本应用改写存档，但不能阻止游戏、Steam Cloud 或其他软件在运行期间更新原文件。因此快照器会等待文件稳定，并为副本建立时间与哈希记录。
- 局域网测试使用 HTTP，应仅在可信任的家庭专用网络启用；公共 Wi-Fi、访客网络和公网端口转发均不在安全边界内。
