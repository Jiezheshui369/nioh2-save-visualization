# 人物状态面板：数据契约与验证

## 最新显示与解析要求（2026-09-25）

- 基础面板体力、精力、妖力只展示上限，例如 `9841/9841` → `9841`、`1297/1297` → `1297`、`0.0/17.8` → `17.8`。
- 仅渲染层格式化明确的数字对；原观察记录、导出档案和研究报告保留原值。已是单值或未识别的值不改写，装备重量和特殊效果不适用此规则。
- 用户明确优先直接解析人物存档，不需要面板计算器。未验证的最终值不通过装备词条相加或截图常量填补。需继续确认其保存形式，不能把数值字节匹配当作字段验证。

## 2026-09-22 的交付边界

角色页八项能力下新增详细属性，移除重复的装备恩宠件数模块。当前支持截图观察，不声称已实现最终人物状态的自动解析。已验证的等级、八项加点、精华、金钱仍来自原解析器，截图记录不会覆盖这些值。

用户七张状态截图整理成 48 项面板记录和 116 条特殊效果；第六、七张中四项完全相同的效果合并并保留两个来源页码。第八张为图标参考，不计入状态截图。仅记录截图可见内容，滚动间可能遗漏的条目不补猜。数值、百分比、A−/AA+ 等档位和无数值开关均保持原意。

- 示例区别：最终妖力上限 17.8 与特殊效果加成 +7.8 分开，不能重复相加。
- “体力 +964”与“体力 +30.0%”不是重复行。
- 截图未提供拍摄时间，因此仅标明整理日期，不把整理时间作为存档或截图时间。
- 等级、八项加点和两种资源一致不证明截图与参考快照具有同一配装。

## 可选扩展

`SaveSnapshot.characterStatus` 为可选字段；旧档案包仍保持 1.0.0，不强迫用户重新生成所有历史档案。

字段包括：`version: 1`、`source: game-screenshots`、`recordedOn`、`captureTime`（可为空）、`referenceSnapshotId`、`screenshotCount`、`groups`、`effects`。每组有标题和条目，每条有 `label`、`value`（空表示游戏显示的无数值效果）、`pages`。

导入校验拒绝无效结构、非法页码、非字符串值和过大列表。界面始终显示“截图记录 · 非自动解析”。参考快照编号不匹配时不显示记录数值；新存档不自动继承旧截图。重新读取游戏存档会使用新解析结果，截图记录应在其独立档案包中保留，而不是假装跟随换装更新。

搜索与分类结果在渲染时计算，不用副作用维护镜像状态；数值使用等宽数字，长效果名可换行。特殊效果默认分类折叠，输入关键词自动展开结果。

## 私有数据与分发

用户的转录脚本、观察档案包及开发验证页面位于 `.local/character-status-20260922/`，不导入生产源码、不进入 public、dist 或 APK。附截图档案使用原有隐私裁剪：隐藏源存档哈希，不包括原始存档、图片或本地路径。原始游戏文件、原始存档及现有快照均不修改。

观察记录随角色档案导出；因此用户主动分享该档案时也会分享这些面板记录。仅保存在本地，不新增网络上传。
